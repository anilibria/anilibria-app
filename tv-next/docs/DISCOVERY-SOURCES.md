# Источники каталога и рекомендаций

## Реализовано

- AniLiberty v1 — первичный идентификатор релиза, эпизоды (UUID), HLS, каталог, расписание.
- `/anime/franchises/release/{releaseId}` — группы франшиз и порядок просмотра по `sort_order`, без исключения текущей части.
- `/anime/releases/recommended?release_id={id}&limit=12` — похожие тайтлы для выбранного релиза. Это рекомендации AniLiberty, не персональная подборка пользователя.
- Дубликаты рекомендаций удаляются по AniLiberty ID; текущий тайтл исключается. Одинаковые названия разных релизов не склеиваются.
- Успешный результат обоих методов кэшируется в памяти процесса на 24 часа, максимум 32 тайтла. Ошибки не превращаются в подтверждённые пустые списки.
- Shikimori / MAL ID и рейтинги из ответа AniLiberty хранятся отдельно, с указанием источника. Отсутствующие значения не заменяются нулём или значением другого сервиса.

Основной релиз показывается до загрузки блоков обогащения. Ошибка одного блока не отключает просмотр или второй блок. Серверные коллекции и история требуют отдельной Bearer-авторизации; локальная библиотека клиента не выдаётся за серверную коллекцию.

## Следующий этап: внешние каталоги

Shikimori / AniList / Jikan пока не подключены. Их токены, условия использования и лимиты ещё не проверены для рабочего клиента. Не предполагаем, что Shikimori ID равен MAL ID; в AniList искать по явному `idMal`. Автоматическое совпадение только по названию запрещено.

Слой обогащения должен быть независим от получения потоков. Предлагаемая модель сопоставления:

```
CatalogIdentity {
  anilibertyId: number | null
  shikimoriId: number | null
  malId: number | null
  anilistId: number | null
  mappingEvidence: explicit-id | reviewed
}
```

Внешняя рекомендация сначала представляет запись внешнего каталога. Она не получает кнопку просмотра до подтверждения соответствующего AniLiberty ID. Наличие релиза в каталоге также не гарантирует доступность потока: ограничения региона/правообладателя и список HLS проверяются отдельно.

Worker-агрегатор, облачное хранилище и выгрузка полной внешней базы не развёрнуты. Контракт будущего агрегатора должен включать происхождение каждого поля, отдельные состояния загрузки/ошибки источников, ограниченный кэш и соблюдение актуальных правил провайдеров. Не пересылать токен аккаунта AniLiberty внешним каталогам.
