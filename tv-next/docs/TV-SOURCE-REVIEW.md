## Остальной объём спецификации

Весь документ принят как целевая модель, а не объявлен реализованным. Последующие обязательные части: полноценное Моё/история/очередь; продолжение с Next Up; отдельное расписание; фильтры с черновиком; OTP после проверки сервера; переключение вида и поиск эпизодов; боковые панели плеера; настройки; реальная проверка на пульте. Внешние API остаются необязательным обогащением.


## Плеер: реализованный проход

- Обычный OK открывает управление; эпизоды и качество доступны кнопками, Menu дублирует вызов эпизодов.
- Панели справа, текущая серия/качество отмечены; Back закрывает панель и возвращает фокус на кнопку.
- Скрытое управление не занимает экран. Back отменяет перемотку, затем скрывает управление, затем выходит.
- Перемотка стрелками задаёт позицию; OK применяет, Back отменяет. Удержание увеличивает шаг.
- Следующая серия определяется следующим фактическим UUID в упорядоченном списке. В конце списка предложение не создаётся.
- Предложение имеет Смотреть сейчас / Отмена, 10-секундный таймер и отключаемый автопереход. Открытие панели и уход приложения в фон отменяют предложение.
- Позиция сохраняется каждые 10 секунд, при паузе, переходе, ошибке и уходе в фон. Качество и состояние паузы сохраняются при возврате Activity.
- Реальный просмотр на ТВ, сетевые разрывы и поведение конкретного пульта ещё не проверены. Очередь, заставки и управление дорожками остаются отдельными задачами.


## Главная: горизонтальные полки

Пользовательское уточнение 22.10.2026 имеет приоритет над исходным документом:

- Новые эпизоды, расписание, франшизы, жанры, видео — отдельные горизонтальные полки. Вертикальные сетки остаются на полных страницах разделов.
- До 9 реальных элементов + отдельная карточка с векторной стрелкой «Все». Короткая или пустая подборка не блокирует полный раздел.
- Стрелка открывает нативную страницу соответствующего раздела; не произвольную страницу сайта.
- Жанры и франшизы используют `/random?limit=9`; подборка хранится в ViewModel до явного обновления главной. Возврат не перезапрашивает случайный состав.
- Полные жанры/франшизы получаются `/anime/genres` и `/anime/franchises`, сортируются по названию. Полная неделя — `/anime/schedule/week`.
- Latest и videos не имеют подтверждённого `page` в схеме: используется возрастающий `limit`. «Показать больше» выводится при заполненной выборке. Неподтверждённое общее количество не отображается.
- Постеры сохраняют изображение целиком; заголовок и краткие сведения под изображением. Широкие карточки для жанров, франшиз, видео. Фокус — рамка и небольшое увеличение без изменения размера ряда.
- Торренты исключены с главной и из вкладок. Дополнительный пункт «Ещё → Торренты» загружает `/anime/torrents/release/{id}` только по действию пользователя; основная загрузка релиза исключает поле torrents.
- Проверки: ограничение девятью элементами, действие стрелки, короткие/пустые полки, одинаковая геометрия широкой карточки и стрелки, сохранение размера постера при фокусе. Реальный телевизионный скриншот после этого прохода ещё не получен.


## Исправление по скриншоту 02:59

Скриншот сетки жанров показал ошибочное переиспользование видео-карточки для всех сущностей. Сверены непосредственно скачанные JS-модули:

- `CardOfGenreLoader.vue.BpKBHKko.js`: CardOfGenre → изображение на всю высоту, `text-center`, нижнее выравнивание `align-end`, подписи внутри изображения `ff-heading`; карточка главной в HomeGenres имеет высоту 320 CSSpx. На TV применены собственные размеры, вертикальная форма сохранена.
- `genresProxy.B9KrqtUi.js`: cover=true, gradient `180deg, rgba(16,16,16,0.0) 0%, rgba(16,16,16,0.20) 70%, rgba(0,0,0,1) 100%`. Эти три точки воспроизведены в Android drawable.
- `CardOfFranchiseLoader.vue.BI-hSWgt.js`: два столбца по 6/12, изображение слева, справа название сверху и метаданные снизу. Франшиза больше не использует карточку видео.

Карточки жанров и франшиз разделены отдельными типами. Изменения действуют и в полках главной, и в полных разделах. Договорённость о горизонтальных полках и девяти элементах со стрелкой сохранена. Тесты проверяют вложенность подписи жанра и расположение информационной панели франшизы. Фактическое отображение на ТВ после изменения ещё не проверено.


Также прочитаны `CardOfReleaseLatestEpisodeWithOverlay.TrTChn5O.js` и `CardOfReleaseLatestEpisodeWithOverlay.BpE4WNc9.css`: при hover изображение получает brightness(5%) contrast(90%), сведения располагаются поверх постера по центру. Для полок latest/schedule это перенесено на фокус D-pad, с постоянной геометрией карточки и соответствующей высотой карточки «Все». Для каталога с подписями сохраняется отдельный режим.


### Последнее уточнение главной

Жанры: **4 карточки → Обновить → Открыть все**. Франшизы: **3 карточки → Обновить → Открыть все**. У каждого ряда собственное обновление (`random?limit=4` для жанров, `random?limit=3` для франшиз), не меняющее остальные данные главной. Во время запроса старые карточки остаются, повторный запрос блокируется, а «Открыть все» остаётся доступным. При ошибке сохраняется старая подборка и появляется повтор. Уход с главной отменяет запрос; его устаревший ответ не меняет другой экран. Остальные полки сохраняют правило 9 + Все.


## Продолжение и видимость заголовка полки

- При переходе фокуса между полками главной в прокручиваемую область включается ближайший заголовок (HEADING или объединённый DAYS). Движение по карточкам внутри полки не меняет горизонтальную позицию.
- Между latest и расписанием добавлен условный горизонтальный блок продолжения: реальное превью эпизода, название релиза, номер/название серии, прогресс и оставшееся время. При отсутствии превью — фирменный знак.
- OK передаёт release ID + точный UUID эпизода непосредственно PlayerActivity, без промежуточной карточки тайтла.
- Незаконченный эпизод имеет приоритет. После завершения предлагается следующий доступный эпизод по серверному порядку, включая дробные и пропущенные номера. Уже завершённые и недоступные серии не становятся Next Up.
- На релиз одна карточка. Пустой блок скрыт. История локальная, аккаунтная синхронизация не объявляется.
- Сохраняются метаданные эпизода, не адреса HLS. При возвращении из плеера состояние обновляется. Для прежних last/position записей метаданные восстанавливаются ограниченной фоновой загрузкой; ошибки не мешают остальной главной.
- Для завершённых релизов при возвращении/явном обновлении главной проверяется свежий список эпизодов, чтобы опубликованная позже следующая серия могла появиться. Таймер проверки ограничен минутой, максимум 16 релизов за проход. Процесс не заявлен как полная серверная синхронизация.
- Тесты: unfinished/Next Up, дробной номер, окончание списка, отсутствующий поток, одна карточка на релиз, корректный заголовок расписания и точный UUID действия карточки.
