# AniLiberty / АниЛибрия — единый UX-проект Android TV

> **Актуальная поправка пользователя, 22.10.2026:** торренты отведены на второй план: только пункт «Ещё» внутри релиза и запрос по открытию. На главной и в основных вкладках торрентов нет. На главной все подборки горизонтальные: до 9 элементов + карточка «Все». Жанры/франшизы случайные с сохранением при возврате.

**Версия:** 2.0 — согласованная спецификация  
**Дата:** 22 октября 2026 года  
**Формат:** текстовые макеты, сценарии пульта, композиция и карта данных  
**Проектный холст:** 1920 × 1080, 16:9  
**Назначение:** основа для детальных экранных макетов и последующей реализации. Этот документ не является готовым приложением.

> **TV-компоновка и взаимодействия — по эталонам open-source TV-клиентов. Наполнение — из живого AniLiberty и его API. Визуальная база — из скачанных архивов сайта.**

Веб-аудит нужен для понимания состава страниц и доступных данных. Десктопная геометрия сайта не переносится на телевизор буквально. Каждый экран заново компонуется вокруг просмотра с дивана и управления пультом.

## 1. Принцип проектирования

### 1.1. Три независимых основания

| Основание | За что отвечает | За что не отвечает |
|---|---|---|
| Open-source TV-клиенты | Расположение зон, сценарии, полки, сетки, панели, пульт, возврат и фокус | Не задают новый бренд и чужую палитру |
| Живой AniLiberty и API | Состав страниц, релизы, эпизоды, метаданные, коллекции, расписание, команда | Не диктуют десктопную компоновку TV |
| Скачанные HTML/CSS/ресурсы AniLiberty | Логотип, типографика, цвета, поверхности, скругления, иллюстрации | Не переносят mouse-hover как единственный способ взаимодействия |

Формула экрана: **задача зрителя → проверенный TV-сценарий → подходящая композиция → оформление AniLiberty → реальные данные**.

### 1.2. Цели продукта

- Продолжить просмотр одним OK с карточки продолжения.
- Найти релиз и начать просмотр без лишних промежуточных экранов.
- Выбрать серию как в коротком, так и в многосерийном произведении.
- Разобраться в доступных частях франшизы.
- Увидеть обновления и расписание озвучки.
- Пользоваться исходными аккаунтом, избранным и коллекциями AniLiberty.
- В любой момент понимать положение фокуса и результат Back.
- Сохранить узнаваемую АниЛибрию: оригинальные материалы, терминологию и команду проекта.

### 1.3. Границы

Это клиент AniLiberty с телевизионным интерфейсом. Статус официального приложения документом не устанавливается. Если проект независимый, соответствующее указание располагается в информации о приложении.

Новый отдельный аккаунт и собственная замена каталога не нужны. AniLiberty определяет доступность просмотра; дополнительные базы только обогащают сведения.

## 2. Источники и уровень подтверждения

### 2.1. Использованные материалы

- Архив главной страницы и её ресурсов.
- Сохранённая страница расписания.
- Архив страницы «Семь рыцарей королевства Марронье» с HTML, CSS, JS и изображениями.
- Архив `aniliberty.top.zip`: состояния эпизодов, связанного, команды и торрентов.
- Переданная спецификация AniLiberty API V1: 71 путь, 80 HTTP-операций.
- Публичные страницы живого сайта и проверенные публичные ответы API.
- Репозитории TV-клиентов и отдельные исходные файлы навигации, эпизодов, продолжения и восстановления фокуса.

### 2.2. Обозначения

| Обозначение | Значение |
|---|---|
| Подтверждено архивом | Присутствует в скачанных материалах |
| Подтверждено вебом | Наблюдалось в живом браузере |
| Подтверждено схемой | Предусмотрено OpenAPI, но сценарий мог не выполняться |
| Подтверждено ответом | Получен публичный ответ API |
| Проектное решение | Предлагаемое устройство TV-клиента |
| Требует проверки | Нельзя считать готовой или проверенной возможностью |

Примеры пользовательского прогресса в макетах условные. Состав релизов, числа и доступность изменяются; наблюдения от 22.10.2026 не являются постоянными значениями.

| Nuvio TV | Эталон согласованности экранов и состояния | Стабильные ID карточек, восстановление рядов, разделение незаконченного и следующего эпизода, контекстные панели |
| Jellyfin Android TV | Эталон сериального просмотра | Эпизоды, очередь, следующая серия, отмена перехода, понятные состояния воспроизведения |

Дополнительные визуальные ориентиры: Fladder и Lampa. Их решения используются для сравнения плотности и информационной иерархии; отдельная архитектура этих проектов не переносится в AniLiberty.

### 3.2. Что было изучено непосредственно в исходниках

| Репозиторий / файл | Подтверждённый принцип | Решение нашего проекта |
|---|---|---|
| Nuvio — `SidebarNavigation.kt` | Разделение выбранного маршрута, фокуса и раскрытого состояния | Красная отметка раздела отдельно от белого фокуса |
| Nuvio — `HomeScreenFocusState.kt` | Хранение ключей рядов, карточек и якорей прокрутки | Возврат к тому же аниме даже после изменения состава ряда |
| Nuvio — `ContinueWatchingNextUpReconciliation.kt` | Согласование InProgress/NextUp и исключение повторов | Одна актуальная карточка продолжения на релиз |
| Nuvio — `FocusRestoreUtils.kt` | Восстановление фокуса после готовности интерфейса | Фокус назначается после появления нужной карточки |
| Nuvio — `EpisodeWatchedProjection.kt` | Согласование просмотренности с текущими и неподтверждёнными изменениями | Устаревший ответ не должен визуально отменять новое действие |
| Nuvio — `EpisodesSidePanel.kt` | Контекстное управление с собственным фокусом и списками | Выбор эпизода внутри плеера без выхода на другой экран |
| Wholphin — `NavigationDrawerAndroid.kt` | Открытие панели связано с фокусом, размеры и анимации адаптируются | Компактное меню, раскрывающееся при входе |
| Wholphin — `SeriesOverviewContent.kt` | Зоны серии, вкладок и рядов имеют собственные точки восстановления | Раздельная память вкладки и выбранного эпизода |
| Wholphin — `FocusableItemRow.kt` | Строка-заглушка или ошибка остаётся фокусируемой | Загрузка и ошибка не создают навигационный тупик |
| Jellyfin — `NextUpViewModel.kt` | Явные состояния следующего эпизода и закрытия предложения | Следующая серия, отмена, отсутствие следующей |
| JetStream — `HomeScreen.kt` | Вертикальная структура с рядами, фиксированной геометрией витрины | При загрузке и смене изображений блоки не прыгают |

Это анализ отдельных компонентов и опубликованных возможностей, а не заявление о полном тестировании каждого чужого приложения.

### 3.3. Правило заимствования

Заимствуются проверенные паттерны сценариев. Любой прямой перенос кода или ресурсов требует отдельной проверки лицензии конкретного файла. Для UX-проекта достаточно ссылок на источники и самостоятельного описания поведения.

| Текст и управление | Inter | Кнопки, подписи, описания |
| Заголовки | Montserrat | Названия и заголовки |

**Roboto не является основным шрифтом интерфейса AniLiberty в исследованных стилях.** Наличие Roboto среди сторонних ресурсов, например reCAPTCHA, не заменяет Inter/Montserrat.

### 4.3. Ресурсы

- Оригинальный логотип/знак из сайта, без перерисовки по памяти.
- Настоящие постеры AniLiberty с сохранением исходной композиции.
- Оригинальные изображения жанров и франшиз.
- Реальные превью эпизодов, если пользователь не скрывает спойлеры.
- Иконки одного начертания с доступными названиями; их внешний характер согласуется с SVG-иконками веба.

Сгенерированная в обсуждении картинка не используется как источник логотипа, обложек, персонажей или названий серий.

### 4.4. Состояния

| Состояние | Вид |
|---|---|
| Открытый раздел | Красная метка и устойчивое выбранное состояние |
| Фокус | Белая рамка и небольшое увеличение при допустимости |
| Выбранный параметр | Галочка / индикатор и подпись |
| Незаконченная серия | Полоса прогресса |
| Просмотренная серия | Галочка и текстовая отметка |
| Недоступное действие | Причина рядом с действием; по возможности понятная замена |

Фокус, активный раздел, избранное, статус коллекции и просмотренность — разные состояния.

## 5. Геометрия и плотность

### 5.1. Единицы

1920 × 1080 — холст макета в пикселях. Нативная реализация использует dp/sp. Указанные далее размеры — проектные ориентиры, а не готовые Android-константы.

### 5.2. Композиционные правила

| Элемент | Стартовое решение |
|---|---|
| Безопасные поля | Ориентир 4–5% по внешним краям; проверка на конкретных TV |
| Боковая панель | Узкая полоса иконок; раскрытие до читаемых подписей поверх контента |
| Главная витрина | Примерно 28–32% высоты первого экрана |
| Каталог | Пять постеров в строке по умолчанию |
| Более плотный каталог | Шесть, только после проверки читаемости |
| Постер | Преимущественно 2:3 |
| Эпизод / продолжение | Преимущественно 16:9 |
| Интервалы | Единая шкала; пространство под рамку и увеличение предусмотрено заранее |
| Длинное название в сетке | Две строки фиксированной высоты |
| Анимация фокуса | Ориентир 120–160 мс, с возможностью уменьшения движения |

Компактность создаётся уменьшением лишних зон и повторов. Уменьшение текста до десктопного размера не используется как основной способ разместить больше.

При прокрутке вниз крупная информация уходит вверх. Один экран не обязан одновременно вмещать большой баннер, два полных ряда и несколько панелей.

## 6. Навигация и фокус

### 6.1. Постоянное меню

| Положение | Пункты |
|---|---|
| Верх | Знак AniLiberty; полный wordmark при раскрытии |
| Основная группа | Поиск → Главная → Релизы → Расписание → Моё |
| Нижняя группа | Поддержать проект → Настройки → Профиль |

Внутри «Релизов»: Каталог / Франшизы / Жанры. Видео команды доступны с главной и из дополнительной навигации. Лишние разделы не превращаются в длинное постоянное меню.

### 6.2. Переходы

| Контекст | Действие | Результат |
|---|---|---|
| Первая карточка ряда | Влево | Вход в меню на текущий раздел |
| Карточка не в начале ряда | Влево | Предыдущая карточка |
| Меню | Вверх/вниз | Движение по пунктам без открытия страниц |
| Меню | OK | Открытие выбранного раздела |
| Меню | Вправо / Back | Закрытие и возврат к прежнему содержимому |
| Горизонтальная полка | Вправо | Следующая карточка с прокруткой полки |
| Сетка каталога | Вправо на последнем столбце | Фокус остаётся в строке; без неожиданного переноса |
| Сетка каталога | Вниз | Следующая строка, ближайший допустимый столбец |
| Панель | Back | Закрыть панель и восстановить кнопку вызова |
| Карточка / вложенная страница | Back | Предыдущий экран и его состояние |
| Плеер с панелью | Back | Закрыть панель |
| Плеер с управлением | Back | Скрыть управление |
| Плеер без панели и управления | Back | Возврат в исходный контекст |

На главной Back из глубины возвращает к началу страницы, затем к навигации; дальнейший Back завершает маршрут стандартным способом. Отдельный диалог выхода по умолчанию не требуется. Стартовое приветствие не попадает в обратную историю.

### 6.3. Контракт состояния

Сохраняются: раздел, фильтры, запрос, сортировка, вид выдачи, ID ряда, ID карточки, положение прокрутки, вкладка релиза, UUID выбранного эпизода.

Индексы используются только как вспомогательные значения. После добавления карточек в начало полки старый индекс не должен выбирать другое аниме.

Если исходная карточка исчезла, фокус попадает на ближайший доступный элемент той же области; затем — на заголовок/повтор, затем — на меню. Ни одна ошибка не оставляет экран без понятной точки управления.

### 6.4. Доступность

- Все кнопки с иконками имеют доступные названия.
- Подсказка не заменяет название кнопки.
- Основные действия доступны без долгого нажатия и специальных клавиш.
- Долгое OK и кнопка Menu могут дублировать контекстные действия.
- Белая рамка сохраняется при отключённом увеличении.
- Открытая панель удерживает фокус внутри.
- Фоновая загрузка не забирает фокус у пользователя.

| Продолжение | Превью, релиз, эпизод, остаток времени, прогресс | Прямой запуск |
| Эпизод | Превью, номер, название при наличии, длительность, прогресс | Запуск эпизода |
| Франшиза | Обложка, название, части, годы | Страница франшизы |
| Жанр | Оригинальная иллюстрация, название, счётчик | Жанровая выдача |
| Видео команды | Превью, заголовок, источник | Поддерживаемый способ просмотра |
| Строка расписания | Постер, название, сведения, доступность | Карточка релиза |

У постера максимум две небольшие плашки. Описание, подробные рейтинги и команда не дублируются на каждой плитке.

Контекстное меню карточки включает доступные в данном месте команды: открыть релиз, продолжить, изменить коллекцию, избранное, очередь, убрать из продолжения. Состав зависит от данных и авторизации.

## 8. Текстовые макеты экранов

### 8.1. Первый запуск

**Задача:** начать просмотр или подключить существующий аккаунт.

**Композиция:** фирменный знак AniLiberty в одной части экрана; логотип, слоган, короткое объяснение и два действия в другой. Размещение не копирует desktop-форму буквально.

> AniLiberty  
> Так звучит аниме!  
> Смотрите аниме в озвучке АниЛибрии и продолжайте на телевизоре.  
> **Продолжить без входа**  
> Войти в аккаунт

Начальный фокус — «Продолжить без входа». При действующей сессии экран пропускается. Авторизация из защищённого действия возвращает пользователя в исходный контекст.

**Данные:** профиль, авторизация; гостевой запуск не требует запроса пользовательских данных.

### 8.2. Главная

**Эталоны:** Nuvio + Wholphin; иерархия выбранного контента — Kodi.

**Первый экран:** слева свёрнутое меню; справа компактная витрина, первый ряд и начало следующего. Витрина не занимает половину экрана.

| Порядок | Наполнение | Источник |
|---|---|---|
| Верх | Заголовок первого раздела | Новые эпизоды |
| 1 | Продолжить просмотр | Локальная история / аккаунтные таймкоды и история |
| 2 | Новые эпизоды, Все / Мои | Latest с `latest_episode`, коллекции, прогресс |
| 3 | Сегодня в расписании | Schedule now |
| 4 | Рекомендуем AniLiberty | Recommended |
| 5 | Франшизы | Франшизы |
| 6 | Жанры | Жанры с изображениями |
| 7 | Видео команды | Media videos |

Гостю без истории первым показывается ряд обновлений. Пустые персональные полки не резервируют пространство.

**Пример информационной области:**

> Название релиза  
> 2026 • Осень • ТВ • 16+  
> Исторический • Комедия  
> До двух строк описания  
> **Смотреть** · Подробнее


OK на продолжении запускает серию. OK на обычном постере открывает релиз. Кнопка «Все» в заголовке открывает полную выдачу. Порядок второстепенных полок можно настроить, но первоначальная конфигурация уже пригодна к использованию.


### 8.3. Релизы / каталог

**Эталоны:** JetStream + Wholphin.

> **Релизы**  
> **Каталог · Франшизы · Жанры**  
> Поиск по каталогу · Фильтры · Сортировка · Вид  
> 2026 × · Осень × · Сбросить  
> Сетка из пяти постеров в строке

Вид по умолчанию — постеры. Дополнительный вид — список с коротким описанием, сохраняющий информационную полноту веба.

Над сеткой остаются активные условия и доступное количество результатов. Следующая страница подгружается без сброса позиции. При ошибке подгрузки уже полученные карточки остаются, в конце появляется «Повторить».

Поиск каталога учитывает фильтры. Глобальный поиск не наследует их молча. Переход из жанра открывает согласованную выдачу с применённым жанром.

**API:** `/anime/catalog/releases`, справочники каталога. GET и POST выдачи — альтернативные формы чтения; POST здесь не означает изменение каталога.

### 8.4. Панель фильтров

**Эталон:** TV-панели с изолированной областью фокуса.

Справа поверх каталога открывается панель приблизительно на треть ширины. В ней прокручиваются параметры; действия закреплены снизу.

| Параметр | Представление |
|---|---|
| Жанры | Список с множественным выбором и поиском при необходимости |
| Тип | Чётко подписанные варианты |
| Статус выхода | Онгоинг / Неонгоинг по серверному справочнику |
| Статус озвучки | Сейчас в озвучке / Озвучка завершена |
| Сезон | Зима / Весна / Лето / Осень |
| Период | От / До, удобный выбор числа с пульта |
| Возраст | Серверные значения |

Внизу: **Применить** / Сбросить. Back отменяет черновик, сохраняя текущую выдачу. После применения фокус переводится к результатам; после отмены — к кнопке фильтров.

Не переносим двухползунковый desktop-слайдер периода буквально: дискретный выбор года удобнее проверять на пульте.

### 8.5. Поиск

**Эталон:** JetStream; быстрый доступ — по смыслу глобального поиска AniLiberty.

> **Поиск**  
> Название аниме [микрофон при поддержке]  
> Недавние запросы / Результаты  
> Сетка найденных релизов

Клавиатура вызывается через OK на поле. После завершения ввода освобождает экран. При отсутствии запроса показывается недавний поиск; при отсутствии результатов — запрос и «Изменить запрос».

Запрос сохраняется после открытия релиза и Back. Предыдущие результаты не исчезают при ошибке следующего запроса. Ответы устаревшего запроса не заменяют новый.

Результаты определяет сервер. Поиск по альтернативным названиям и нечёткое совпадение не обещаются без проверки. Улучшение ранжирования возможно, но неполную серверную выдачу нельзя считать полным каталогом.

**API:** `/app/search/releases?query=...`. В текущей схеме отдельная пагинация этого метода не описана.

### 8.6. Карточка релиза

**Эталоны:** Jellyfin + Wholphin; компактная информационная иерархия сравнивается с Lampa.

**Композиция:** постер занимает приблизительно пятую часть области контента, сведения справа. Боковые обновления desktop-сайта не забирают отдельную постоянную колонку.

| Левая зона | Правая зона |
|---|---|
| Оригинальный постер | Русское название |
| | Оригинальное название |
| | Год • сезон • тип • возраст |
| | Жанры |
| | Статус, день расписания, доступные серии |
| | Описание до трёх строк и «Полностью» |
| | **Смотреть / Продолжить** · Избранное · Коллекция · Ещё |

Под шапкой: **Эпизоды / Связанное / Рекомендуем / Работа над релизом**.

Первые эпизоды начинаются на первом экране. При переходе вниз шапка сворачивается до названия и кнопки продолжения. Отдельные вкладки не дублируются теми же большими полками ниже.

| Состояние просмотра | Основное действие |
|---|---|
| Не начат | Смотреть с первого доступного эпизода |
| Есть незаконченный | Продолжить · номер эпизода |
| Закончен эпизод и есть следующий | Смотреть следующий доступный |
| Все доступные просмотрены, релиз продолжается | Все доступные просмотрены; ожидание, повтор через дополнительное действие |
| Завершённый релиз просмотрен | Смотреть заново |
| Эпизодов нет | Эпизоды ещё не опубликованы |
| Просмотр ограничен | Причина ограничения и доступные сведения |

В «Ещё»: полное описание, моя оценка, очередь, торренты, открыть страницу на телефоне. Комментарии не представлены как готовая рабочая функция: в проверенной странице веба вкладка отключена.

**API:** релиз; франшизы; рекомендации для `release_id`; члены команды; пользовательский прогресс, избранное, коллекция, оценка.

### 8.7. Эпизоды внутри релиза

> **Эпизоды** · Просмотрено 1 из 3  
> Поиск по номеру / названию · Порядок · Превью / Список · Действия  
> Карточки серий

Иллюстративный единый профиль для макетов: первый эпизод просмотрен, второй не закончен на 11:05, третий не начат. Это не данные аккаунта пользователя.

Режим «Превью»: номер, название при наличии, длительность, отметка/прогресс. Режим «Список»: те же сведения в строках.

Стартовый проектный порядок — от первого к последнему; «Сначала новые» доступен и запоминается. Стартовый фокус — на актуальном эпизоде продолжения. Вариант порядка из веба не должен менять логический выбор следующего эпизода.

Основное OK запускает. Явное меню действий: продолжить / с начала, просмотрено / не просмотрено, добавить в очередь. Долгое OK дублирует меню.

### 8.8. Полный список эпизодов

**Эталоны:** Jellyfin + Wholphin.

| Слева | Справа |
|---|---|
| Превью выбранного эпизода | Диапазоны 1–25 / 26–50… |
| Номер, название, длительность | Поиск |
| Состояние просмотра | Список или карточки |
| **Смотреть** | Прокрутка с сохранением выбранной серии |

Диапазоны применяются к фактическому порядку, не требуют непрерывных целых номеров. Эпизод 12.5 или пропуск номера не ломает навигацию. Следующий определяется доступными элементами, а не арифметикой «номер + 1».

Не создаём полный экран списка ради трёх серий. Он нужен для длинного релиза или явного выбора «Все эпизоды».

### 8.9. Связанное и вся франшиза

**Эталоны композиции:** медиатеки Jellyfin/Kodi; данные связей — AniLiberty.

Вкладка: название франшизы, части, текущий релиз, «Все части». Если связей нет — короткое пустое состояние.

Полная страница:

> **Название франшизы**  
> Годы • Частей в AniLiberty • Эпизодов • Продолжительность  
> **Порядок AniLiberty**  
> #1 — Название • тип • год • прогресс  
> #2 — Название • тип • год • прогресс

Связка сортируется по `sort_order`. Количество релизов называется «частями», если нет оснований считать их сезонами. Внешняя классификация может обозначать приквел, сиквел, фильм, OVA и спин-офф, но не переписывает оригинальный состав автоматически.

Следующая часть предлагается после финала только при однозначном соответствии. В остальных случаях — «Открыть франшизу».

**API:** `/anime/franchises`, конкретная франшиза, франшизы релиза. Пагинация полного списка франшиз в переданной схеме не описана; клиентская выдача строится после проверки ответа и объёма.

### 8.10. Рекомендации

> **Вам также может понравиться**  
> **AniLiberty / По жанрам / Дополнительно**  
> Одна согласованная сетка результатов выбранного основания

Связанное остаётся отдельной вкладкой фактических отношений. Рекомендации не подписываются «похожий сюжет», если такого основания нет.

На первом плане — релизы с доступным соответствием в AniLiberty. Внешнее произведение без соответствия имеет справочный режим и не получает кнопку просмотра.

Для каждой рекомендации сохраняется источник. Дубликаты по подтверждённым ID убираются; разные озвучки и версии не сливаются только по похожему названию.

### 8.11. Расписание

**Основа данных:** оригинальная страница. **TV-композиция:** выбранный день + список, с явными осями движения.

> **Расписание**  
> Пн / Вт / Ср / Чт / Пт / Сб / Вс  
> Все / Из коллекций / Избранное  
> Постер — Название — опубликованный эпизод или ожидание

Влево/вправо в днях выбирает день. Вниз переводит к релизам; вверх из первой строки возвращает к выбранному дню. При возврате восстанавливаются день, фильтр и релиз.

По умолчанию выбран текущий день с явно согласованным часовым поясом. Нельзя без проверки молча считать серверное `today` локальным днём пользователя.

`26:20` — длительность эпизода, не время публикации. Отдельно отображаются опубликованный эпизод, следующий ожидаемый номер и полный сезон. Справка сохраняет предупреждение веба о возможном отклонении дня выхода.

Фильтр «Из коллекций» по умолчанию означает все коллекции пользователя, как подписано; рядом может быть уточнение статусов, включая «Смотрю». Это не скрытая подмена всех коллекций одним статусом.

### 8.12. Моё

**Эталоны:** Wholphin + Jellyfin.

> **Моё**  
> **Продолжить / Коллекции / Избранное / История / Очередь**

| Подраздел | Вид |
|---|---|
| Продолжить | Карточки с текущим или следующим эпизодом |
| Коллекции | Пять статусов и выдача выбранного |
| Избранное | Отдельная сетка |
| История | Последние фактические просмотры |
| Очередь | Упорядоченный список эпизодов |

Статусы коллекций: Запланировано, Смотрю, Просмотрено, Отложено, Брошено. Избранное не является шестым статусом.

Гость видит локальные историю, продолжение и очередь. Аккаунтные разделы объясняют преимущества входа. После входа возможен перенос локальной истории с явным решением конфликтов; автоматическое затирание серверной истории не допускается.

### 8.13. Панель коллекции и оценка

Небольшая панель поверх релиза:

> **В коллекцию**  
> ○ Запланировано  
> ○ Смотрю  
> ○ Просмотрено  
> ○ Отложено  
> ○ Брошено  
> Удалить из коллекции

Текущий статус отмечен. После успешного сохранения панель закрывается, краткое подтверждение не перехватывает фокус.

Оценка — отдельная панель 1–10 с текущим значением и удалением. Собственная оценка, средний рейтинг AniLiberty, Shikimori и MAL не смешиваются. Пустой рейтинг не отображается как ноль. Средний рейтинг AniLiberty по схеме пересчитывается фоново, поэтому немедленное изменение общего балла не обещается.

### 8.14. Плеер

**Эталоны:** Jellyfin + Nuvio.

Видео полноэкранное; постоянного меню нет. Интерфейс скрывается во время просмотра.

| Зона при открытом управлении | Содержание |
|---|---|
| Верх | Название • номер/название серии |
| Низ | Время • шкала • длительность |
| Основные действия | Предыдущий / Пауза / Следующий |
| Дополнительные | Эпизоды / Очередь / Качество / Настройки |
| Контекстные | Пропустить опенинг / Следующая серия |

| Кнопка | Поведение |
|---|---|
| OK при скрытом интерфейсе | Показать управление, фокус на паузе |
| OK на элементе | Выполнить действие |
| Влево/вправо при скрытом интерфейсе | Открыть понятный режим перемотки |
| Влево/вправо на шкале | Изменять целевую позицию |
| Удержание стрелки | Ускорить шаг |
| OK в перемотке | Подтвердить позицию |
| Back в перемотке | Отменить предварительный выбор |
| Play/Pause | Непосредственная пауза/воспроизведение |
| Back | Сначала закрыть панель, затем управление, затем выйти |

Панель качества открывается сбоку; панель эпизодов/очереди сохраняет контекст видео. После закрытия восстанавливается вызвавшая кнопка. Наличие дорожек и субтитров определяется реальным потоком; переключатели не рисуются заранее.

В конце предлагается следующая доступная серия с «Смотреть сейчас / Отмена». Таймер запускается только в активном просмотре; открытая панель или явное действие отмены не должны неожиданно переключать серию. Автопереход отключается. Защита от бесконтрольного ночного просмотра — дополнительное проектное поведение.

Автопропуск эндинга не должен без проверки обрезать сцену после титров. Неоднозначные интервалы трактуются после проверки реального плеера и семантики API.

### 8.15. Жанры

Оригинальные тематические изображения, название и `total_releases`. Сетка плиток. OK открывает релизы жанра с понятным заголовком и возможностью продолжить исследование в общем каталоге.

Числа из скриншотов не зашиваются в интерфейс. Неизвестный счётчик скрывается без подстановки нуля.

### 8.16. Видео команды

Сетка карточек 16:9: заголовок, источник, доступные сведения. Это самостоятельный тип содержимого, не аниме-релиз и не эпизод.

Веб использует встроенный YouTube. API возвращает URL и ID, а не гарантированный поток для нативного плеера. На TV предусматриваются поддерживаемое открытие источника и резервная QR-ссылка. Полноценное нативное воспроизведение каждого ролика требует отдельной проверки.

### 8.17. Авторизация и профиль

Предпочтительный сценарий TV — подтверждение на телефоне.

| Слева | Справа |
|---|---|
| QR проверенного адреса привязки | Короткая инструкция |
| Код устройства | Срок действия |
| Обновить код | Ожидание / подтверждено / ошибка |
| Отмена | Альтернативный доступный способ |

Схема содержит выдачу OTP, привязку авторизованным пользователем и обмен на токен. Готовая страница привязки и поведение ожидания не считаются проверенными только из наличия маршрутов.

OTP в модели ответа представлен строкой и может начинаться с нуля, а входные поля описаны числом. Отображение сохраняет исходные цифры; формат передачи и ведущие нули проверяются интеграционным тестом.

Профиль: имя, аватар, состояние синхронизации, выход, управление аккаунтом на телефоне. Переключение аккаунта изолирует локальные данные разных пользователей. Сессии, социальные сети и уведомления веба не превращаются в обещанные серверные функции TV без контракта.

## 10. История, продолжение и очередь

### 10.1. Разные сущности

| Сущность | Смысл |
|---|---|
| Коллекция | Намерение пользователя относительно релиза |
| Избранное | Отдельная персональная отметка |
| История | Фактические просмотры |
| Прогресс | Позиция и просмотренность эпизода |
| Продолжение | Вычисляемое ближайшее действие |
| Очередь | Выбранная последовательность эпизодов |

### 10.2. Продолжение

1. Найти актуальный незаконченный эпизод релиза.
2. При отсутствии такого — следующий доступный после завершённого.
3. Исключить дублирующую карточку Next Up при наличии незаконченной.
4. Если продолжения нет, не создавать кнопку на несуществующую серию.
5. Удаление из продолжения не удаляет коллекцию и избранное.

Порог автоматической просмотренности — проектная политика, требующая проверки на эпизодах с титрами, короткими выпусками и спецсериями. Ручная отметка имеет явный приоритет. Отсутствие серии в одной странице истории не доказывает отсутствие прогресса.

### 10.3. Синхронизация

- Сразу обновлять локальное представление собственного действия.
- Сохранять позицию периодически, при паузе, смене серии и выходе; частоту определить отдельно.
- Объединять неотправленные изменения одного эпизода.
- Не давать кратковременно закэшированному ответу сервера откатить только что сохранённый прогресс.
- Различать локальное неподтверждённое изменение и серверное состояние.
- `since` использовать после проверки формата ответа и границ времени.
- Не выбирать максимальную позицию автоматически: пользователь мог осознанно начать заново.
- Перед повтором записи проверять, что активен тот же аккаунт.

### 10.4. Очередь

В вебе очередь присутствует. В переданной спецификации отдельного контракта её серверной синхронизации нет. Начальное решение — локальная очередь с идентификаторами эпизодов, изменением порядка и удалением. Автопереход внутри релиза и пользовательская очередь различаются; UI объясняет, какая последовательность сейчас играет.

### 11.5. Прогресс

Запись POST таймкодов включает `release_episode_id`, `time`, `is_watched`. История постраничная и может включать эпизод и релиз. Общий ответ timecodes описан в схеме необычно, как компактные элементы; нормализация проверяется на реальном аккаунте.

Маршруты таймкодов релиза/эпизода по документации могут иметь кэш порядка 1–2 минут. Это важно для мгновенного возврата из плеера: свежая локальная позиция остаётся до согласования.

### 11.6. Статусы и сортировки

| Назначение | Значения |
|---|---|
| Коллекции | `PLANNED`, `WATCHING`, `WATCHED`, `POSTPONED`, `ABANDONED` |
| Озвучка | `IS_IN_PRODUCTION`, `IS_NOT_IN_PRODUCTION` |
| Выход | `IS_ONGOING`, `IS_NOT_ONGOING` |
| Сортировки каталога | `FRESH_AT_DESC`, `FRESH_AT_ASC`, `RATING_DESC`, `RATING_ASC`, `YEAR_DESC`, `YEAR_ASC` |

Подписи берутся из справочников. Сортировка по году не называется «недавно добавлено». `FRESH_AT_DESC` — «Обновлены недавно», а не гарантированный порядок появления новых эпизодов.

У коллекций и избранного разные наборы справочников. Нельзя автоматически обещать одинаковую серверную сортировку для обоих разделов.

### 11.8. Подтверждённые расхождения схемы и ответов

- В latest обнаружен `latest_episode`, важный для обновлений.
- Media videos в проверке вернул массив, тогда как схема описывает объект с `data`.
- `episodes_total` может быть `null`.
- `background_covers` может быть пустым массивом.
- Названия эпизодов и интервалы пропуска могут отсутствовать независимо друг от друга.
- Рейтинги могут содержать `null` и ноль голосов.

При реализации сохраняются реальные контрольные ответы; адаптер данных допускает документированные резервные формы. Ошибочные и неизвестные структуры не превращаются молча в «пустую коллекцию».

### 11.9. Загрузка данных

Первый экран не ждёт всех источников. Сначала основной контент AniLiberty; затем пользовательские отметки и дополнительные сведения. IDs избранного/коллекций и пакетный список релизов используются для уменьшения повторных обращений. `include`/`exclude` применяются после проверки фактического состава полей.

Отдельный сервер-агрегатор не обязателен для базового приложения. Он рассматривается позднее для внешних метаданных и сопоставления. Видео и пользовательские токены не отправляются такому посреднику без необходимости.

## 16. Справочное приложение: живой веб

### 16.1. Для чего выполнен аудит

Аудит определяет состав информации и существующие сценарии. Его результаты не требуют повторять desktop-колонки и мышиное управление. Замечания веба ниже — справка для улучшения клиентского UX, а не план обязательного изменения чужого сайта.

### 16.2. Условия

Проверка в живом браузере, гостевой режим, окно 1363 × 936, 22 октября 2026 года по Москве. Дополнительно получены публичные ответы API. Мобильная адаптация, реальный TV и авторизованные операции в этом проходе не проверялись.

### 16.4. Проверенные взаимодействия

- Поиск «Ранма» в каталоге и глобальном окне вернул части «Ранмы», а также произведения со словами «ранга/ранговым» — замечание к релевантности.
- Несуществующий запрос дал понятное пустое состояние.
- Запрос каталога сохранился после Back и после перезагрузки.
- После возврата из релиза фокус находился на BODY — для TV требуется явное восстановление.
- Глобальный поиск открылся и закрылся Escape.
- Выбор вторника показал три релиза соответствующего дня.
- «Связанное» у «Семи рыцарей» показало отсутствие франшизы.
- «Работа над релизом» показала Dikobraz — Кодирование HEVC.
- Торренты показали раздачи и варианты AVC/HEVC/AV1; скачивание не выполнялось.
- После рекламного этапа первый эпизод воспроизводился; счётчик рос, пауза работала.
- При возврате у первой серии появился гостевой прогресс. Синхронизация с аккаунтом не проверена.

### 16.5. Наблюдения для проектирования

| Наблюдение | Применение на TV |
|---|---|
| Крупная шапка отодвигает серии | Сворачиваемая шапка и видимые первые эпизоды |
| Обновления повторяют открытый релиз | Исключать бессмысленные дубли |
| У ряда иконок отсутствует доступное имя | Подписанные действия и корректные accessibility labels |
| В проверенных каталоге/карточке нет семантического H1 | Логическая структура заголовков |
| Содержание франшиз называют сезонами | Применять «части» при неоднородном составе |
| Поиск смешивает близкие словоформы | Сохранять серверный поиск, отдельно улучшать ранжирование |

### Последнее уточнение главной

Жанры: **4 карточки → Обновить → Открыть все**. Франшизы: **3 карточки → Обновить → Открыть все**. У каждого ряда собственное обновление (`random?limit=4` для жанров, `random?limit=3` для франшиз), не меняющее остальные данные главной. Во время запроса старые карточки остаются, повторный запрос блокируется, а «Открыть все» остаётся доступным. При ошибке сохраняется старая подборка и появляется повтор. Уход с главной отменяет запрос; его устаревший ответ не меняет другой экран. Остальные полки сохраняют правило 9 + Все.
